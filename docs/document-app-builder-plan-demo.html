详细修改计划

计划目标是在现有 OpenAI Agents SDK 模板生成能力上，升级为“文档应用构建器”。核心变化是：解析上传的待识别图片/文档后先生成字段草案，用户在结构化页面确认字段，再生成 prompt、cleaner 和输出配置；固定 Excel 空模板通过 {{field_key}} 定义填充槽位。

1. 产品入口与权限

  • 继续放在现有 /admin 的 AI 生成模板区域，不新增公开页面。
  • 入口改名为“文档应用构建器”，支持样本文档、固定 Excel 填报模板、对话创建、复制模板四种起点。
  • 后端继续要求 tenant_admin / super_admin，并新增 session owner 校验。
  • 验证：非管理员 403；管理员只能读取自己创建的草案 session。

2. 字段草案数据模型

  • 新增或固化 field_schema：label、field_key、data_type、extraction_hint、sample_value、source、required、review_enforced、output_targets。
  • 字段候选来源支持 ai_detected、manual、cloned_template；Excel 的 excel_placeholder 作为输出槽位来源记录。
  • 草案状态支持 draft、needs_review、confirmed、excluded。
  • 验证：field_key 唯一、合法命名、不能与系统字段冲突；confirmed 字段才允许发布。

3. API 合同调整

  • 保留现有 /api/sdk/sessions，扩展为 builder session，不破坏已有流程。
  • 新增或拆分：解析待识别图片/文档、扫描 Excel 填充槽位、更新字段草案、生成对话补丁、确认字段、生成 prompt、发布模板。
  • 对话接口只返回 patch，不直接写最终模板；前端接受后再调用草案更新接口。
  • 验证：每个接口有 Pydantic schema、权限测试、owner 测试、错误码测试。

4. OpenAI Agents SDK 流程

  • Doc Analyzer Agent：基于 OCR、表格、图片区域和已有模板，生成字段草案。
  • Field Patch Agent：把用户对话转成字段 patch，并给出理由和风险提示。
  • Prompt Agent：只基于 confirmed 字段生成 extraction_prompt_template。
  • Code Agent：基于字段类型、校验规则和输出目标生成 cleaner 预览。

5. 空 Excel 模板填充输出

  • 上传空 xlsx 模板后扫描所有文本单元格里的 {{field_key}}，得到需要填充的目标字段。
  • 同时上传待识别图片/文档，OpenAI Agents SDK 从图片/文档解析这些字段的具体值。
  • 输出时复制原 workbook，并把抽取结果写入对应占位符；保留样式、合并单元格、图片和公式。
  • 验证：用提供的复杂 Excel 空模板和待识别图片做回归，检查字段值被写入且样式未丢失。

6. 前端组件拆分

  • DocumentAppBuilder 作为容器，替代继续膨胀的单体 wizard。
  • BuildModePicker、DocumentParsePanel、FieldDraftTable、FieldInspector、PatchReviewPanel、PublishReview 分开实现。
  • 字段改动后标记 prompt/code stale，要求重新生成预览后才能发布。
  • 验证：前端 build、lint，关键状态用组件测试或至少手动路径验证。

7. 数据库与存储

  • document_templates 增加 output_mode、field_schema、excel_template_file_id、builder_metadata 等配置。
  • 空模板 xlsx 放对象存储或现有上传目录，数据库只保存引用和 hash。
  • 生成的 Excel 结果写入新的输出记录，供用户下载和审计。
  • 验证：迁移可回放；旧模板默认 output_mode 为 bitable，不影响现有流程。

8. 分阶段落地

  1. MVP：字段草案编辑页 + confirmed 字段生成 prompt/code，保持现有多维表格输出。
  2. 第二阶段：空 Excel 模板上传、占位符扫描、图片解析结果填充和下载。
  3. 第三阶段：对话补丁、模板克隆差异对比、更多文档类型向导。
  4. 每阶段单独验证，避免一次性改动 LLM pipeline、存储和输出链路。

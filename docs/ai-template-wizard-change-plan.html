NeoFlow / AI 模板生成向导

修改计划展示页

目标是把“管理员上传样本文档 → OCR → AI 推荐模板 → 人工确认 → 生成 Prompt / 清洗代码 → 写入 Supabase”的流程， 落成一个可操作、可回滚、可验证的前后端闭环。

6 核心流程步骤，从上传 OCR 到提交模板。
5+ 前端重点：字段、示例、Prompt、代码、提交状态。
7 后端接口覆盖 session、analyze、confirm、prompt、code、commit、delete。
最小 只改 AI 模板向导相关文件，不重构现有文档处理链路。

关键假设

展示对象

面向管理员和开发者，用来确认这次 AI 模板向导要改哪些页面、接口和服务。

实现边界

保留现有后台配置页结构，只新增 AI 生成模板入口和向导，不改已有上传、审核、飞书推送流程。

数据落点

模板、字段、Few-shot 示例、Prompt 模板写入 Supabase；清洗代码先做预览和 session 保存。

页面流程

1

上传样本文档

管理员上传 PDF / 图片，后端保存临时文件并执行 OCR。

2

OCR 摘要

页面展示文件名、置信度、OCR 文本，作为后续 AI 分析输入。

3

AI 分析

Agent 推荐文档类型、部门、字段、样例值和 Few-shot 示例。

4

人工确认

管理员编辑模板名称、code、字段、审核规则、示例 JSON。

5

生成预览

生成 Prompt 和清洗代码预览，允许提交前手工微调。

6

写入 Supabase

创建模板、字段和示例，并刷新后台模板列表。

文件修改计划

文件 修改内容 验证方式
api/routes/sdk.py 新增 AI 模板生成 API，包括上传 OCR、分析、确认、生成 Prompt、生成代码、提交和删除 session。 pytest tests/test_sdk/ -v
sdk/models.py 定义 session、分析结果、字段、示例、确认模板、提交结果等 Pydantic 模型。 API response model 校验通过。
sdk/agents/* 实现文档分析、Prompt 生成、清洗代码生成和 orchestrator 编排。 mock agent 输出，验证 API 流程。
services/template_service.py 支持模板自定义 extraction_prompt_template，并提供创建模板能力。 构建 prompt 时优先使用自定义模板。
web/src/components/admin/AiTemplateWizard.tsx 新增多步向导 UI：上传、分析、编辑字段、编辑示例、生成预览、提交。 npm run build，浏览器检查页面。
web/src/services/sdk.ts 封装前端 SDK API 调用，提交时携带最终 Prompt / cleaner code。 TypeScript 编译通过。
web/src/pages/AdminConfig.tsx 新增“AI 生成模板”入口和 Tab，提交后刷新模板列表。 管理员配置页能打开并进入向导。

接口合同

Session 生命周期

POST /api/sdk/sessions GET /api/sdk/sessions/{id} DELETE /api/sdk/sessions/{id}

负责创建、读取和清理临时 AI 模板生成会话。

AI 生成链路

POST analyze POST prompt POST code

每一步独立调用，方便页面按需重试和展示预览。

提交合同

POST commit prompt 可覆盖 cleaner_code 可选

提交前以页面最终编辑内容为准，避免丢失管理员手工修订。

验证清单

前端构建：npm run build 必须通过。
SDK 测试：pytest tests/test_sdk/ -v 必须通过。
页面检查：管理员配置页能看到“AI 生成模板”入口。
数据检查：提交后模板列表刷新，字段和示例可在后台继续编辑。
Prompt 检查：手动编辑后的 Prompt 能随 commit 写入模板。
边界检查：非管理员访问 SDK 路由返回 403。

风险和不在范围

本计划不包含生产级执行模型生成的清洗代码、不改现有结果表结构策略、不改认证授权模型、 不迁移历史数据、不重写已有文档处理 worker。清洗代码先作为预览和元数据保留，进入运行时前需要单独做安全审查。

Review 重点

1. 功能边界

本版实现“管理员上传样本文档 - OCR - AI 分析 - 确认模板 - 生成 prompt - 写入 Supabase”的第一版闭环。清洗代码只做 preview，不自动 import 或执行。

2. 命名冲突处理

仓库已有本地 agents/ 业务包，官方 OpenAI Agents SDK 也使用 agents 导入名。新实现通过 distribution 路径隔离加载 SDK， 避免覆盖现有 agents.workflow。

3. 数据库合同

新迁移给 document_templates 增加 extraction_prompt_template 和 cleaner_module。 模板服务读取 prompt 字段时优先使用自定义模板。

端到端流程

1

上传样本文档并 OCR

前端 AiTemplateWizard 调用 POST /api/sdk/sessions。 后端保存文件到 uploads/sdk_sessions，复用 ocr_service.process_document() 得到 OCR 文本和置信度。

2

Agent 分析文档

doc_analyzer_agent 输入 OCR 文本、文件名和已有部门列表， 输出推荐文档类型、模板 code、部门、字段和 few-shot 示例。

3

管理员确认模板配置

前端允许编辑模板名称、code、描述、提取模式、逐页提取开关和字段提示， 然后调用 /confirm-template 保存到内存 session。

4

生成 Prompt 并提交

prompt_agent 生成带 {ocr_text} 占位符的提取 prompt。 commit 阶段创建模板、字段和 few-shot 示例，字段写入继续复用现有 template_service.create_field() 的 ADD COLUMN 行为。

后端改动

新增 SDK 包

  • sdk/models.py：Session、分析结果、确认请求、commit 结果模型。
  • sdk/session.py：带 TTL 的内存 session store。
  • sdk/openai_agents_runtime.py：隔离加载 OpenAI Agents SDK。
  • sdk/agents/*：文档分析、prompt、code preview 和 orchestrator。

新增 API 路由

  • api/routes/sdk.py：管理员专用 SDK API。
  • api/main.py：注册 sdk_router 到 /api/sdk。
  • 权限沿用 CurrentUser.is_tenant_admin()，普通用户返回 403。

模板服务

  • create_template()：供 commit 阶段创建模板。
  • build_extraction_prompt()：优先使用 extraction_prompt_template。
  • get_admin_templates() 回传新字段，便于前端后续展示。

依赖与配置

  • requirements.txt 新增 openai-agents>=0.7.0。
  • config/settings.py 新增 SDK_MODEL_ID、SDK_API_KEY、SDK_BASE_URL、SDK_TEMPERATURE。
  • 为空时 fallback 到现有 LLM 配置。

前端改动

管理页入口

AdminConfig.tsx 新增 AI 生成模板 tab 和按钮。 该 tab 只要求先选择部门，不要求先选已有模板。commit 成功后刷新模板列表。

向导组件

AiTemplateWizard.tsx 使用四步视觉流程展示 OCR、AI 分析、确认配置、 写入 Supabase。字段可编辑，Prompt 可预览和修改。

类型合同

web/src/types/index.ts 增加 SDK session、analysis、field、example、 commit result 等 TS 类型；同时把两个空 interface 改为 type alias，避免 lint 噪音。

API Service

web/src/services/sdk.ts 封装上传、分析、确认、生成 prompt、 生成 code preview 和 commit 调用，复用现有 Axios 鉴权拦截器。
